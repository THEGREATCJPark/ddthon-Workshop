# U3 Frontend — Business Rules (Client-side)

> U3 프론트가 강제하는 **클라이언트 측 규칙**. 백엔드 계약(FROZEN v0.1.0)이 강제하는 서버 규칙은 재정의하지 않으며, 프론트는 이를 소비/표시하고 UX 수준 규칙만 정의한다.
> 각 규칙 뒤 `(Q#)` 는 근거 질문(functional-design-questions).

---

## 1. 인증 / 세션 (F1·F2)

- **BR-A1** 토큰은 `localStorage` 에 저장하며, 새로고침·재실행 시 유효 토큰이면 재사용한다. (Q4=A)
- **BR-A2** 고객 `tablet_token` 이 유효(`now < expires_at`)하면 자동 로그인하여 메뉴를 표시한다. (FR-C1)
- **BR-A3** 401 또는 만료 시 처리 (Q20=D):
  - 관리자: `access_token` 삭제 → 로그인 화면 전환.
  - 고객: 만료된 `tablet_token` 삭제 → 재인증 화면 전환. `store_id`/`table_no` 는 입력 프리필로만 사용.
- **BR-A4** `table_password` 는 **localStorage 에 저장하지 않으며, 저장된 자격으로 조용한 자동 재발급(silent re-login)을 시도하지 않는다.** (Q20=D)
- **BR-A5** 재인증은 루프를 만들지 않는다: 재인증 화면 전환 후 사용자의 명시적 재로그인만 새 토큰을 발급한다.

## 2. 장바구니 (F1)

- **BR-C1** 장바구니는 `localStorage` 단일 키(`to_cart`)에 저장하며, 저장 시점 `store_id`/`table_no` 메타를 포함한다. (Q5=C)
- **BR-C2** 현재 TabletContext 와 저장된 store/table 이 불일치하면 장바구니를 자동 초기화한다. (Q5=C)
- **BR-C3** 항목 수량은 1 이상이며, `updateQty` 로 0 이하가 되면 항목을 제거한다.
- **BR-C4** 동일 `menu_id` 를 추가하면 신규 항목이 아니라 수량을 증가시킨다.
- **BR-C5** 총액 `total = Σ(unit_price × qty)` 는 저장하지 않고 렌더 시 계산한다.
- **BR-C6** 장바구니에 `name`·`unit_price` 스냅샷을 보관해 주문 확인 화면에 표시하되, 서버 전송 payload 는 `{menu_id, qty}` 만 포함한다. (Q6=B, 계약 §5.3)

## 3. 주문 (F1)

- **BR-O1** 빈 장바구니로는 주문할 수 없다(제출 차단 + 안내 토스트).
- **BR-O2** 주문 성공 시: 주문번호 표시 → 장바구니 비우기 → **5초 후** 메뉴로 자동 리다이렉트. (Q9=A, FR-C1)
- **BR-O3** 주문 실패 시: 에러 메시지 표시, **장바구니 유지**(비우지 않음).
- **BR-O4** 주문 내역은 **현재 세션 주문만** 표시한다(과거 세션 제외). (계약 `GET /api/orders/current`)

## 4. 관리자 대시보드 / 상태 (F2)

- **BR-D1** 주문 상태 값은 `PENDING`/`IN_PROGRESS`/`DONE` 3종만 사용하며, 표시 라벨은 대기중/준비중/완료로 매핑한다. (계약 §6)
- **BR-D2** 상태 변경은 3개 버튼 중 선택으로 수행하고 현재 상태를 강조한다. (Q13=A)
- **BR-D3** 신규 주문(`order.created`) 수신 시 해당 테이블 카드를 하이라이트 후 수 초간 페이드아웃한다. 반영은 SSE 수신 즉시(요구 2초 이내). (Q12=A)
- **BR-D4** 파괴적 동작(주문 삭제·세션 종료)은 커스텀 확인 모달을 거친다. (Q15=A)
- **BR-D5** 테이블 필터는 칩 다중 선택이며, 선택이 없으면 전체를 표시한다. (Q14=B)
- **BR-D6** 카드 총액/목록은 SSE 이벤트(`order.deleted.new_table_total`, `table_session.ended`)로 갱신하며 클라이언트가 임의로 재계산하지 않는다(서버 값 신뢰). (계약 §8)

## 5. 이력 / 세션 (F2)

- **BR-H1** 세션 종료 확인 모달 승인 시 `end-session` 호출 → 카드 리셋(총액 0). (Q15=A)
- **BR-H2** 과거 이력은 날짜 프리셋(오늘/어제/최근 7일) 또는 커스텀 범위로 조회한다. (Q16=B, `date_from`/`date_to`)
- **BR-H3** 이력은 시간 역순으로 표시한다.

## 6. 메뉴 관리 (F2)

- **BR-M1** 등록/수정 시 필수 필드(카테고리·이름·가격)를 검증하며, 가격은 0 이상 정수.
- **BR-M2** 삭제는 확인 모달을 거친다.
- **BR-M3** 노출 순서는 `display_order` 오름차순을 따르며, 재정렬은 `reorder` 로 반영한다.

## 7. 렌더링 / 피드백 / 디바이스 (횡단)

- **BR-X1** 서버·사용자 유래 문자열은 `escapeHtml()` 로 이스케이프 후 `innerHTML` 렌더한다. (Q2=A)
- **BR-X2** 성공/실패 피드백은 토스트로 표시하고 일정 시간 후 자동 소멸한다. (Q18=A)
- **BR-X3** 이미지 로드 실패 시 공통 플레이스홀더로 교체한다. (Q10=A)
- **BR-X4** SSE 끊김 시 3초 고정 간격으로 재연결한다. (Q17=A)
- **BR-X5** 레이아웃 기준: 고객 = 태블릿 가로 고정, 관리자 = 데스크톱. (Q19=A)
