# 테이블오더 서비스 — 요구사항 문서 (Requirements)

> Source of Truth: `requirements/table-order-requirements.md`, `requirements/constraints.md`
> 본 문서는 위 원본을 **변경/삭제하지 않고**, 확인 질문 답변을 반영하여 구현 관점으로 정리한 것입니다.

## 1. Intent Analysis (의도 분석)

| 항목 | 내용 |
|---|---|
| **User Request** | 테이블오더 서비스를 AI-DLC v1.0.1로, 4명·반나절 팀 실습으로 개발. 전체 흐름(Inception→Unit 분해→병렬 Construction→통합→Build/Test)을 완주하며 동작하는 MVP를 만든다. |
| **Request Type** | New Project (greenfield) |
| **Scope Estimate** | Multiple Components (고객 웹UI, 관리자 웹UI, 백엔드 API, 데이터 저장소, 실시간 SSE) |
| **Complexity Estimate** | Moderate (여러 컴포넌트 + 세션/실시간/상태 관리, 단 범위는 MVP로 한정) |
| **Depth** | Standard (기능·비기능 요구사항 정리, 반나절 제약에 맞춰 NFR·인프라·문서는 최소화) |

**핵심 원칙**
- 기능 요구사항과 constraints는 임의 변경/삭제 금지.
- 우선순위 = 핵심 vertical slice가 실제로 동작: **메뉴 조회 → 장바구니 → 주문 생성 → 관리자 주문 확인 → 주문 상태 변경**.
- production 수준 NFR/인프라/문서로 범위를 확대하지 않는다.

## 2. Technical Decisions (확인 질문 반영)

| 결정 | 선택 | 근거 |
|---|---|---|
| 백엔드 | **Python + FastAPI** | SSE·JWT 구현이 간단, 반나절에 적합 (Q1=A) |
| 프론트엔드 | **순수 HTML + CSS + Vanilla JS** (정적 파일 제공, 빌드 도구 없음) | 프론트 빌드 환경 제거, 핵심 흐름·통합 집중 (Q2=A) |
| 데이터 저장소 | **SQLite** (파일 기반, 영속) | 인프라 없이 영속성 확보, 반복 데모 용이 (Q3=A) |
| 실시간 모니터링 | **SSE (Server-Sent Events)** — polling 대체 안 함 | 승인된 기능 요구사항 3.2.2 유지 (Q4=A) |
| 시드 데이터 | **자동 시드** (샘플 매장 + 관리자 계정 + 카테고리별 메뉴 + 테이블 수 개) | 데모/Happy Path 즉시 검증 (Q5=A) |
| 실행 범위 | **로컬 실행만** (단일 명령 기동) | 배포보다 전체 워크플로우 완주 우선 (Q6=A) |

## 4. Functional Requirements (기능 요구사항)

원본 요구사항 3장을 기준으로 하며, MVP 범위(원본 4장)에 포함된 항목을 구현 대상으로 한다.

### 4.1 고객용 (Customer)
- **FR-C1 테이블 태블릿 자동 로그인/세션 관리** — 관리자 1회 초기설정(매장 식별자, 테이블 번호, 테이블 비밀번호) 후 저장 정보로 자동 로그인. (원본 3.1.1)
- **FR-C2 메뉴 조회/탐색** — 메뉴 화면이 기본 화면. 카테고리별 분류, 상세(메뉴명·가격·설명·이미지), 카테고리 빠른 이동. 카드형 레이아웃, 터치 버튼 최소 44x44px. (원본 3.1.2) ⭐ *핵심 흐름*
- **FR-C3 장바구니 관리** — 추가/삭제, 수량 증감, 총액 실시간 계산, 비우기, **클라이언트 로컬 저장(새로고침 유지)**. 서버 전송은 주문 확정 시에만. (원본 3.1.3) ⭐ *핵심 흐름*
- **FR-C4 주문 생성** — 최종 확인 → 확정. 성공 시 주문 번호 표시, 장바구니 자동 비우기, 메뉴 화면 자동 리다이렉트(5초 표시 후). 실패 시 에러 표시 + 장바구니 유지. 주문 정보: 매장·테이블 식별, 메뉴 목록(명·수량·단가), 총액, 세션 ID. (원본 3.1.4, 4장) ⭐ *핵심 흐름*
- **FR-C5 주문 내역 조회** — 시간순 정렬, 상세(번호·시각·메뉴/수량·금액·상태[대기중/준비중/완료]). **현재 테이블 세션 주문만** 표시(이용 완료 세션 제외). 페이지네이션/무한스크롤. (원본 3.1.5)

### 4.2 관리자용 (Admin)
- **FR-A1 매장 인증** — 매장 식별자 + 사용자명/비밀번호. 16시간 세션, **JWT 기반**, 새로고침 시 유지, 16시간 후 자동 로그아웃. 비밀번호 **bcrypt 해싱**, 로그인 시도 제한, 세션 기반 인증. (원본 3.2.1)
- **FR-A2 실시간 주문 모니터링** — **SSE로 실시간 업데이트(2초 이내)**. 그리드/대시보드(테이블별 카드, 총 주문액, 최신 n개 미리보기), 카드 클릭 시 상세, 신규 주문 시각 강조, 테이블별 필터. (원본 3.2.2) ⭐ *핵심 흐름(확인+상태변경)*
- **FR-A3 테이블 관리** — (1) 테이블 태블릿 초기 설정(번호·비밀번호, 16시간 세션 생성, 자동 로그인 활성화) (2) 주문 삭제(확인 팝업, 즉시 삭제, 총액 재계산) (3) 테이블 세션 시작/종료(이용 완료 시 주문을 과거 이력으로 이동, 현재 주문/총액 0 리셋, 새 고객 시작 가능) (4) 과거 주문 내역 조회(테이블별 역순, 날짜 필터). OrderHistory 저장, 세션 ID 그룹화, 완료 시각 기록. (원본 3.2.3)
- **FR-A4 주문 상태 변경** — 대기중/준비중/완료 상태 전환. (원본 3.2.2) ⭐ *핵심 흐름*
- **FR-A5 메뉴 관리** — 카테고리별 조회, 등록(명·가격·설명·카테고리·이미지 URL), 수정, 삭제, 노출 순서 조정. 필수 필드·가격 범위 검증. (원본 3.2.4)

### 4.3 핵심 우선 흐름 (Priority Vertical Slice)
`FR-C2 메뉴 조회 → FR-C3 장바구니 → FR-C4 주문 생성 → FR-A2 관리자 주문 확인 → FR-A4 주문 상태 변경`
이 경로가 end-to-end로 동작하는 것을 최우선 검증 대상으로 한다.

## 5. Non-Functional Requirements (비기능 요구사항 — MVP 최소 수준)

- **NFR-1 실시간성**: 신규 주문/상태 변경이 관리자 화면에 SSE로 2초 이내 반영. (원본 3.2.2)
- **NFR-2 세션**: 관리자 16시간 JWT 세션; 테이블 세션은 첫 주문~이용 완료까지 라이프사이클로 관리. (원본 3.1.1/3.2.1/부록)
- **NFR-3 보안(요구사항 명시 수준)**: bcrypt 비밀번호 해싱, JWT 인증, 로그인 시도 제한. (확장 Security는 미적용)
- **NFR-4 데이터 영속성**: SQLite 파일에 매장/메뉴/주문/OrderHistory/세션 저장.
- **NFR-5 클라이언트 상태**: 장바구니는 클라이언트 로컬 저장(새로고침 유지), 서버 전송은 확정 시.
- **NFR-6 사용성**: 터치 친화 UI(버튼 최소 44x44px), 카드형 메뉴, 신규 주문 시각 강조.
- **NFR-7 실행 단순성**: 로컬에서 단일 명령으로 기동, 시드 데이터 자동 생성.
- *반나절 제약상 성능 튜닝, 확장성, HA/DR, 고급 관측성 등은 범위에서 제외.*

## 6. Out of Scope (constraints.md 준수)
결제/PG/영수증/환불/포인트, OAuth·SNS·2FA/OTP, 이미지 최적화·CMS·광고, 모든 알림(푸시/SMS/이메일/소리), 주방 전달·재고, 데이터 분석·매출 리포트·재고·직원 권한·예약·리뷰·다국어, 외부 연동(배달/POS/소셜/지도/번역). (원본 constraints 1~7 전체)

## 7. 핵심 요구사항 요약
- 고객: 메뉴 조회 → 장바구니 → 주문 → (현재 세션) 주문 내역.
- 관리자: 로그인(JWT 16h) → SSE 실시간 모니터링 → 주문 상태 변경/삭제 → 테이블 세션 종료(과거 이력화) → 메뉴/테이블 관리.
- 스택: FastAPI + Vanilla JS + SQLite + SSE, 로컬 실행, 시드 데이터 포함.
- 확장(Security/Resiliency/PBT) 미적용, 단 요구사항 명시 보안은 구현.
