# 사용자 스토리 (User Stories)

> **구성 방식**: 하이브리드 — 페르소나로 크게 나누고 그 안에서 사용자 여정 순서로 정렬 (Q1=D)
> **인수 조건**: Given / When / Then (Q2=A) · **세분화**: 기능 단위 중간 크기 (Q3=A) · **범위**: MVP 핵심 (Q5=A)
> ⭐ = 핵심 우선 흐름(vertical slice): 메뉴 조회 → 장바구니 → 주문 생성 → 관리자 주문 확인 → 상태 변경
> 각 스토리는 INVEST를 만족하도록 작성했고, 요구사항 FR-ID로 트레이스합니다.

---

## Epic A — 고객 (Persona: 다인)

### US-C1. 테이블 태블릿 자동 로그인 (FR-C1)
**As a** 고객, **I want** 별도 로그인 없이 테이블 태블릿에서 바로 주문 화면에 진입하기를, **so that** 대기 없이 즉시 주문할 수 있다.

**Acceptance Criteria**
- Given 관리자가 매장 식별자·테이블 번호·테이블 비밀번호로 1회 초기 설정을 완료했다,
  When 태블릿에서 앱을 연다,
  Then 저장된 정보로 자동 로그인되어 메뉴 화면이 표시된다.
- Given 자동 로그인 정보가 로컬에 저장되어 있다,
  When 브라우저를 새로고침한다,
  Then 재로그인 없이 세션이 유지된다.

---

### US-C2. 메뉴 조회 및 탐색 (FR-C2) ⭐
**As a** 고객, **I want** 카테고리별로 정리된 메뉴를 상세 정보와 함께 보기를, **so that** 원하는 메뉴를 쉽게 찾아 선택할 수 있다.

**Acceptance Criteria**
- Given 앱에 진입했다,
  When 화면이 로드된다,
  Then 메뉴 화면이 기본으로 표시되고 카테고리 목록과 카드형 메뉴가 보인다.
- Given 메뉴 목록이 표시된다,
  When 한 메뉴 카드를 본다,
  Then 메뉴명·가격·설명·이미지가 표시된다.
- Given 여러 카테고리가 있다,
  When 특정 카테고리를 선택한다,
  Then 해당 카테고리 메뉴로 빠르게 이동한다.
- Given 터치 UI 환경,
  Then 주요 버튼은 최소 44x44px 크기다.

---

### US-C3. 장바구니 관리 (FR-C3) ⭐
**As a** 고객, **I want** 선택한 메뉴를 장바구니에 담고 수량/총액을 조정하기를, **so that** 주문 전에 내용을 확정할 수 있다.

**Acceptance Criteria**
- Given 메뉴 화면,
  When 메뉴의 담기를 누른다,
  Then 장바구니에 추가되고 총 금액이 실시간 갱신된다.
- Given 장바구니에 항목이 있다,
  When 수량을 증가/감소하거나 항목을 삭제한다,
  Then 수량과 총액이 즉시 반영된다.
- Given 장바구니에 항목이 있다,
  When 페이지를 새로고침한다,
  Then 장바구니 내용이 클라이언트 로컬 저장으로 유지된다.
- Given 장바구니에 항목이 있다,
  When 장바구니 비우기를 누른다,
  Then 모든 항목이 제거된다.
- 주의: 장바구니 데이터는 주문 확정 시에만 서버로 전송된다.

---

### US-C4. 주문 생성 (FR-C4) ⭐
**As a** 고객, **I want** 장바구니 내용을 최종 확인 후 주문으로 확정하기를, **so that** 주방/매장에 주문이 전달된다.

**Acceptance Criteria**
- Given 장바구니에 1개 이상 항목이 있다,
  When 주문 확정을 누른다,
  Then 매장·테이블 식별정보, 메뉴 목록(명·수량·단가), 총액, 세션 ID를 포함해 서버에 주문이 생성된다.
- Given 주문이 성공했다,
  When 응답을 받는다,
  Then 주문 번호가 표시되고 장바구니가 자동으로 비워지며, (표시 후) 메뉴 화면으로 자동 리다이렉트된다.
- Given 주문이 실패했다,
  When 에러 응답을 받는다,
  Then 에러 메시지가 표시되고 장바구니 내용은 유지된다.

---

### US-C5. 현재 세션 주문 내역 조회 (FR-C5)
**As a** 고객, **I want** 현재 테이블 세션의 주문 이력을 보기를, **so that** 무엇을 주문했고 진행 상태가 어떤지 확인할 수 있다.

**Acceptance Criteria**
- Given 현재 세션에 주문이 있다,
  When 주문 내역을 연다,
  Then 주문이 시간순으로 정렬되어 번호·시각·메뉴/수량·금액·상태(대기중/준비중/완료)가 표시된다.
- Given 이전(이용 완료) 세션 주문이 존재한다,
  When 주문 내역을 본다,
  Then 현재 세션 주문만 표시되고 과거 세션 주문은 제외된다.

## Epic B — 매장 관리자 (Persona: 사장님)

### US-A1. 매장 인증 / 세션 (FR-A1)
**As a** 관리자, **I want** 매장 계정으로 안전하게 로그인하고 세션이 유지되기를, **so that** 반복 로그인 없이 매장을 관리할 수 있다.

**Acceptance Criteria**
- Given 등록된 매장 식별자·사용자명·비밀번호,
  When 로그인한다,
  Then bcrypt로 저장된 비밀번호를 검증하고 JWT 기반 16시간 세션이 시작된다.
- Given 로그인된 상태,
  When 브라우저를 새로고침한다,
  Then 세션이 유지된다.
- Given 세션이 시작된 지 16시간이 지났다,
  When 요청한다,
  Then 자동 로그아웃되어 재인증이 필요하다.
- Given 로그인 시도가 반복 실패한다,
  Then 로그인 시도 제한이 적용된다.

---

### US-A2. 실시간 주문 모니터링 (FR-A2) ⭐
**As a** 관리자, **I want** 들어오는 주문을 실시간 그리드 대시보드로 보기를, **so that** 주문을 놓치지 않고 즉시 대응할 수 있다.

**Acceptance Criteria**
- Given 관리자 대시보드가 열려 있다,
  When 새 주문이 생성된다,
  Then SSE를 통해 2초 이내에 해당 테이블 카드에 반영된다.
- Given 대시보드,
  Then 테이블별 카드 그리드로 표시되고 각 카드에 총 주문액과 최신 주문 미리보기가 보인다.
- Given 신규 주문이 도착한다,
  Then 해당 카드가 시각적으로 강조(색상/애니메이션)된다.
- Given 특정 테이블 카드를 클릭한다,
  Then 해당 테이블의 전체 주문 상세(테이블 번호·주문 번호·시각·메뉴/수량·총액)가 표시된다.
- Given 여러 테이블이 있다,
  When 테이블별 필터를 적용한다,
  Then 선택한 테이블의 주문만 표시된다.

---

### US-A3. 주문 상태 변경 (FR-A4) ⭐
**As a** 관리자, **I want** 주문 상태를 대기중→준비중→완료로 변경하기를, **so that** 조리/서빙 진행 상황을 관리하고 고객에게 반영할 수 있다.

**Acceptance Criteria**
- Given 특정 주문,
  When 상태를 대기중/준비중/완료 중 하나로 변경한다,
  Then 변경이 저장되고 대시보드에 반영된다.
- Given 관리자가 주문 상태를 변경했다,
  When 고객이 주문 내역을 조회하거나 갱신한다,
  Then 변경된 상태가 표시된다.
  (참고: 고객 화면으로의 실시간/SSE 푸시는 요구사항 범위가 아니며 추가하지 않는다. 실시간 SSE는 US-A2 관리자 대시보드에 한정.)

---

### US-A4. 주문 삭제 (직권 수정) (FR-A3-2)
**As a** 관리자, **I want** 특정 주문을 삭제하기를, **so that** 잘못된/취소 주문을 정리하고 총액을 정정할 수 있다.

**Acceptance Criteria**
- Given 특정 주문,
  When 삭제 버튼을 누른다,
  Then 확인 팝업이 표시된다.
- Given 확인 팝업,
  When 확인한다,
  Then 주문이 즉시 삭제되고 테이블 총 주문액이 재계산되며 성공 피드백이 표시된다.

---

### US-A5. 테이블 이용 세션(주문 세션) 관리 (시작/종료·과거 이력) (FR-A3-3, FR-A3-4)
> **세션 정의**: 여기서의 "테이블 이용 세션(= 주문 세션)"은 **고객이 해당 테이블에서 첫 주문을 시작한 시점부터 이용 완료 처리까지의 영업 라이프사이클**을 뜻한다. 이는 US-A6의 태블릿 인증(자동 로그인) 세션과는 **별개의 개념·라이프사이클**이며, 하나가 시작/종료된다고 해서 다른 하나가 함께 시작/종료되지 않는다.

**As a** 관리자, **I want** 고객의 테이블 이용 세션을 시작/종료하고 과거 주문 이력을 조회하기를, **so that** 새 고객이 이전 주문 없이 시작할 수 있고 이력을 추적할 수 있다.

**Acceptance Criteria**
- Given 테이블에 진행 중인 이용 세션이 없다,
  When 해당 테이블에서 첫 주문이 생성된다,
  Then 새로운 테이블 이용 세션(주문 세션)이 시작되고 이후 주문이 이 세션에 그룹화된다.
- Given 테이블 이용 완료 처리,
  When 이용 세션 종료를 확인한다(확인 팝업),
  Then 해당 이용 세션의 주문이 과거 이력(OrderHistory, 세션 ID 그룹화, 완료 시각 기록)으로 이동하고, 테이블 현재 주문 목록·총액이 0으로 리셋되어 새 고객이 새 이용 세션을 시작할 수 있다.
  (참고: 이용 세션 종료는 태블릿의 자동 로그인/인증 세션을 로그아웃시키지 않는다.)
- Given 과거 내역 버튼,
  When 누른다,
  Then 테이블별 과거 주문이 시간 역순으로(번호·시각·메뉴·총액·이용 완료 시각) 표시되고 날짜 필터가 가능하며 닫기로 복귀한다.

---

### US-A6. 테이블 태블릿 초기 설정 (인증/자동 로그인 세션) (FR-A3-1)
> **세션 정의**: 여기서의 "세션"은 **태블릿의 자동 로그인을 위한 인증/설정 세션**(디바이스 인증 자격)이다. 이는 US-A5의 고객 테이블 이용(주문) 세션과는 **별개의 개념·라이프사이클**이다. 태블릿 인증 세션은 디바이스가 로그인 상태를 유지하기 위한 것으로, 고객이 앉고 일어나는 이용 세션의 시작/종료와 연동되지 않는다.

**As a** 관리자, **I want** 테이블 번호·비밀번호를 설정하고 태블릿 인증(자동 로그인) 세션을 생성하기를, **so that** 해당 테이블 태블릿이 이후 자동 로그인으로 동작한다.

**Acceptance Criteria**
- Given 관리자 화면,
  When 테이블 번호와 테이블 비밀번호를 입력해 설정한다,
  Then 태블릿 자동 로그인을 위한 인증 세션(유효기간 16시간)이 생성되고 설정 정보가 저장되어 해당 태블릿의 자동 로그인이 활성화된다.
  (참고: 이 인증 세션은 고객의 테이블 이용 세션[US-A5]과 독립적이다.)

---

### US-A7. 메뉴 관리 (FR-A5)
**As a** 관리자, **I want** 메뉴를 등록/수정/삭제하고 노출 순서를 조정하기를, **so that** 판매 메뉴를 최신 상태로 유지할 수 있다.

**Acceptance Criteria**
- Given 메뉴 관리 화면,
  When 카테고리별로 메뉴를 조회한다,
  Then 등록된 메뉴가 카테고리별로 표시된다.
- Given 신규 메뉴 입력(메뉴명·가격·설명·카테고리·이미지 URL),
  When 등록한다,
  Then 필수 필드와 가격 범위가 검증된 뒤 저장되어 고객 메뉴에 반영된다.
- Given 기존 메뉴,
  When 수정 또는 삭제한다,
  Then 변경이 저장되고 반영된다.
- Given 여러 메뉴,
  When 노출 순서를 조정한다,
  Then 고객 화면의 표시 순서가 변경된다.
